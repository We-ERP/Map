# خريطة البلوكات الذكية — مصر

تطبيق خرائط تفاعلي (HTML5 / CSS3 / Vanilla JavaScript ES6+) يقسّم أي منطقة في مصر إلى بلوكات مرقمة، ويعرض القطع والشوارع وأرقام البيوت، ويصدّر الخرائط بدقة طباعة عالية. يعمل بالكامل على الاستضافة الثابتة (GitHub Pages) بدون مفاتيح API مدفوعة.

المنطقة الافتراضية عند الفتح: **المرج - القاهرة**.

---

## المزايا

- **خرائط متعددة الطبقات:** CARTO (داكن/فاتح حسب الثيم)، OpenStreetMap، Esri للقمر الصناعي، وهجين (قمر + أسماء).
- **بحث عن أي منطقة في مصر** عبر Nominatim، مع جلب الحدود الإدارية الحقيقية.
- **بيانات من OpenStreetMap** عبر Overpass API: الشوارع، المباني، وأرقام البيوت وأسماء الشوارع.
- **استكمال ذكي للبيانات الناقصة:** إذا كانت المنطقة تفتقر لأرقام مسجّلة، يولّد التطبيق قطعًا على جانبي الشوارع بأرقام متسلسلة (زوجي/فردي)، ويعلّمها بوضوح كـ "مقدّرة".
- **تقسيم مكاني بعدد قابل للتحديد:** أزرار سريعة لـ 35 و 53 بلوكًا، أو أي رقم مخصص (حتى 200). التقسيم بخوارزمية K-Means ثم Voronoi مقصوص بحدود المنطقة.
- **لوحة تفاصيل (Inspector):** عند النقر على أي بلوك أو قطعة تظهر الإحداثيات والمساحة واسم الشارع ورقم البيت.
- **بحث فوري** برقم البلوك، أو اسم الشارع، أو رقم البيت.
- **تصدير عالي الدقة:**
  - بلوك واحد مع تكبير تلقائي وترويسة ومفتاح خريطة.
  - الخريطة كاملة في صورة واحدة.
  - كل البلوكات دفعة واحدة في ملف ZIP مرقّم.
  - PNG بقياس 300 DPI مدمج في الملف، أو JPEG.
- **واجهة عربية RTL** بخط Cairo، ووضع ليلي ونهاري.

## التشغيل محليًا

التطبيق ملفات ثابتة، ويحتاج اتصالًا بالإنترنت لتحميل المكتبات والخرائط. لا يعمل بفتح الملف مباشرة من المتصفح بسبب قيود الوحدات، لذلك شغّل خادمًا محليًا:

```bash
cd egypt-gis-blocks
python -m http.server 8000
```

ثم افتح `http://localhost:8000` في المتصفح.

---

## النشر على GitHub Pages

1. أنشئ مستودعًا جديدًا على GitHub (مثلاً `egypt-gis-blocks`).
2. ارفع ملفات المجلد إلى جذر المستودع (`index.html` يجب أن يكون في الجذر).
3. من **Settings → Pages** اختر:
   - Source: `Deploy from a branch`
   - Branch: `main` / `(root)`
4. بعد دقائق يصبح الموقع متاحًا على `https://<username>.github.io/egypt-gis-blocks/`.

## تجهيز بيانات منطقة مسبقًا (اختياري)

استخدم السكريبت لسحب بيانات منطقة وحفظها محليًا، فيحمّل التطبيق المنطقة فورًا:

```bash
pip install requests shapely
python fetch_egypt_gis.py --query "مدينة نصر، القاهرة" --out data/nasr-city.geojson
```

ثم أضف الملف إلى `CONFIG.prebuilt` في `app.js`:

```js
prebuilt: [
  { match: ['المرج'], file: 'data/marg-cairo.geojson' },
  { match: ['مدينة نصر'], file: 'data/nasr-city.geojson' },
],
```

## تغيير المنطقة الافتراضية

في `app.js` عدّل الكائن `CONFIG`:

```js
defaultQuery: 'المرج، القاهرة، مصر',
defaultLabel: 'المرج - القاهرة',
```

## ملاحظات مهمة عن البيانات

**القطع المقدّرة ليست سجلات رسمية.** عندما تفتقر المنطقة لأرقام مسجّلة في OpenStreetMap، يولّد التطبيق قطعًا وأرقامًا تقديرية بناءً على موقع الشوارع. هذه القطع:

- تظهر بخط **متقطع** في الخريطة.
- تُعلَّم بعبارة "قطعة مقدّرة وليست سجلاً رسمياً" في لوحة التفاصيل.
- تُحسب نسبتها وتظهر في شريط المعلومات أسفل لوحة التحكم.

لا تستخدم هذه البيانات في أي إجراء قانوني أو عقاري دون مراجعة جهة رسمية.

## القيود التقنية

- **Overpass API** مجاني ومحدود بالمعدل. المناطق الكبيرة جدًا قد تتطلب وقتًا أطول أو تفشل مؤقتًا. الحل: استخدم `fetch_egypt_gis.py` لتجهيز الملف مسبقًا.
- **صور الخلفية في التصدير:** تُضاف عند توفر الخادم بسماح CORS. إذا تعذّر تحميلها، تُصدَّر الخريطة بالحدود والشوارع والقطع على خلفية موحدة دون فقدان للبيانات.
- **الذاكرة:** الصور الكبيرة جدًا (مثل 4000 بكسل مع 53 بلوكًا في ZIP) تستهلك ذاكرة المتصفح. إذا فشل التصدير، اختر دقة أقل.
- **التخزين المحلي:** يخزّن التطبيق نتائج Overpass في `localStorage` لتسريع التحميل التالي، ويتجاوز التخزين تلقائيًا إذا كان الحجم كبيرًا.
